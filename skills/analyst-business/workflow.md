# analyst-business 工作流

三阶段。**事实层（Phase 0–1）禁止与推理层（Phase 2）并行**——铁律 5。
每个 phase 有独立产物 + bar 自检，可暂停 review 再继续。

工作目录：`~/analyst-skills/runs/<公司-slug>/`

---

## Phase 0 — 信源勘探（source-map）

**目标**：定位卖方材料原文，识别它在卖哪个故事，搭好取证地图。**不做判断**。

做什么：
1. **定位一手卖方材料**：招股书（港股招股书/聆讯后资料集）、F-1/红鲱鱼、财报、融资 PR。拿到原文 URL，不靠转述。
2. **识别承重卖方 claim**（3–5 条）：公司在卖哪个故事？瞄准哪类估值倍数？哪几句是承重墙？
3. **定位它在价值链/技术栈哪一层**（调 analyst-tech 判断或 hints）。
4. **锁定对标集**：公司自己选了哪类 comp？买方该用哪类 comp（如 AI infra：CoreWeave/Lambda vs 软件 comp）？
5. **抓发行要素**：估值/募资规模、募资用途、基石投资者、上市章节（如 18C）。

产物：`00-source-map.md`（材料清单 + 承重 claim 候选 + comp 集 + 发行要素 + 已识别缺口）。

**bar**：拿到一手招股书/财报原文 ≥1 份；承重 claim 列出 ≥3 条；估值与募资用途明确。达不到 → 标缺口 / M-xxx。

## Phase 1 — 事实层（忠实复原两套叙述）

**目标**：把"卖方怎么说"和"买方该查什么"都建到不漏的库里。**仍不下裁决**。

### 1A — 卖方 pitch 复原（steelman）
按公司**最强**版本复原每条承重 claim：讲什么、摆什么证据、想让你得出什么、瞄哪类估值。
质检：公司自己人看了会点头。

### 1B — 三表测谎 + 交易层取证
拉硬数字当测谎仪（见 `frameworks/ipo-transaction-readout.md`）：
- 毛利率 / capex-营收 / 折旧-营收 / 单客户集中度 / 人员结构
- 募资用途、估值倍数 vs comp、基石成色、对赌/优先股/赎回权、老股转让/锁定期
- **风险因素章节**逐条摘（法律强制的认罪书）

### 1C — Level B 客户取证（裸算力命题的主战场）
客户为什么买它、合同结构（take-or-pay/按量/锁定期）、替代选项（自建/云厂/别家）、是真优选还是被迫无替代（regime-distortion，见 real-strength-stack.md）。
招股书不老实说 → 缺口走 M-xxx。

产物：`01-facts.md`（卖方 claim 库 + 数字库 + 客户/合同证据 + 风险因素摘 + 信源标注 + 已识别缺口）。

**bar**：每条承重 claim 有对应数字/证据可验或明确标缺口；三表关键口径到手；风险因素读完。

## Phase 2 — 推理层（买方逐 thread 剥茧 → 收敛裁决）

**目标**：用买方纪律逐条剥茧，并排呈现，最后钉到价钱上。

1. **逐承重 claim 出两栏 thread**（模板 `templates/sell-buy-thread.md`）：卖方 steelman ‖ 买方剥茧 → 本质。
2. **从价钱倒推**：发行价隐含哪组必须成立的假设？逐条用剥茧结果检验，哪条撑不住、差额在哪。
3. **收敛裁决**：值不值这个价 / 什么价才值 / 在什么 regime 下成立。标信心等级 + 反向考虑。
4. **未知清单**：缺口 | 为什么重要 | 试过什么 | 怎么解开。
5. **Handoff Hints**：→ analyst-tech（要它验哪条技术 claim）/ → analyst-media（故事点）。

产物：`02-readout.md`（并排 threads + 价钱倒推 + 裁决 + 未知清单 + hints）。

**bar**：每条承重 claim 都收敛到裁决；裁决钉在具体价钱/倍数上；未知清单非空。

## M-xxx 手动接力协议

遇登录态/反爬/付费墙/私密内容/需访谈，**不硬撑**。用统一格式向用户发起任务：

```
M-001 | 需要什么 | 为什么重要 | 我试过什么 | 请你做什么（最小成本路径）
```

客户访谈类（Level B 取证）尤其常触发——这是最真实却最难拿的视角。
