# Wardley Mapping（价值链 × 演化阶段映射）

Simon Wardley 提出的战略地图。把"用户需要什么"和"组件演化到哪一步"放在一张图里，让技术路线选择变成可视化决策。

## 地图的两个轴

```
↑ 可见性高（用户直接感知）
|
|   [User Need]
|       |
|   [Component A]
|       |
|   [Component B]
|       |
|   [Infrastructure C]
|
↓ 可见性低
  ←——————————————————————————————→
   Genesis  Custom  Product  Commodity
   （演化阶段）
```

- **Y 轴**：可见性（Value Chain），从用户感知的"产品"一路往下到"基础设施"
- **X 轴**：演化阶段，每个组件处在 4 个阶段之一

## 演化的 4 个阶段

| 阶段 | 特征 | 典型例子 |
|---|---|---|
| **Genesis** | 全新、定制、不确定 | 实验室原型、单一项目 |
| **Custom-built** | 少数玩家、定制实现 | 高端咨询、专属系统 |
| **Product** | 多家供应商、可购买的成熟产品 | SaaS、商用软件 |
| **Commodity / Utility** | 标准化、按需付费、近乎电力 | 云计算、电力、互联网 |

## 为什么对技术分析师特别有用

1. **看穿"组件位置错配"**。最常见的失败：把还在 Genesis 阶段的组件当成 Commodity 卖（"自动驾驶 L4 即将普及"），或反之，把已 Commodity 的组件当成差异化卖。
2. **预测演化方向**。所有组件天然往右演化（Genesis → Commodity），慢的是阻力大的组件（监管、生态、习惯）。
3. **识别战略机会**。当一个 Genesis 组件即将演化到 Product 时，是平台/工具型公司的最佳入场点。

## 应用流程

### Step 1：定义用户需求（图最顶端）

例：「用户需要：能在家中完成多种家务的人形机器人」

### Step 2：自上而下拆解价值链

每一层都问"上一层需要什么组件才能实现"：

```
家用机器人服务
├── 控制大脑（多模态决策）
├── 具身策略（动作生成与执行）
├── 感知系统（视觉 + 触觉 + 听觉）
│   ├── 视觉模型
│   ├── 触觉传感器
│   └── 听觉/语音模型
├── 硬件本体
│   ├── 关节执行器
│   ├── 电池
│   └── 结构材料
└── 基础设施（云端、地图、电信网络）
```

### Step 3：给每个组件标演化阶段

| 组件 | 阶段 | 依据 |
|---|---|---|
| 视觉模型 | Product → Commodity | 开源模型成熟，API 化 |
| 控制大脑 | Custom → Product | 各家路线分歧，未标准化 |
| 具身策略 | Genesis → Custom | 仍在实验室阶段 |
| 关节执行器 | Custom-built | 高度定制，少数玩家 |
| 触觉传感器 | Genesis | 几乎无成熟商业方案 |
| 电池 | Product → Commodity | 工业链成熟 |
| 云端基础设施 | Commodity | 完全公用 |

### Step 4：识别战略机会与陷阱

**机会**：
- 处于 Genesis → Custom 阶段且**很快**会演化到 Product 的组件 → 工具/平台型创业机会
- 例：具身策略生成框架（类似 PyTorch 之于深度学习）

**陷阱**：
- 把 Commodity 组件包装成差异化卖点（"我们用了最先进的云计算"）
- 处于"上游已 Commodity 但本身仍在 Genesis" 的尴尬位置（既没有成本优势，又没有规模红利）

### Step 5：标演化方向与速度

每个组件画一个向右的箭头，长度表示未来 3 年的演化速度估计。

- 慢演化的组件 = 长期可垄断 = 长期 Power 来源
- 快演化的组件 = 短期窗口 = 适合快进快出

## 应用示例（简化）

> **题目**：判断一家做"具身 AI 平台"的公司（提供机器人开发框架 + 仿真 + 评估）的战略位置

**Wardley Map 简版**：

```
↑ 可见性高
  [机器人客户的产品体验]                  ← Genesis~Custom
       |
  [应用层框架 / 仿真环境 / 评估工具]     ← Custom → Product（公司的位置）
       |
  [视觉/语言/动作大模型]                  ← Product
       |
  [GPU / Cloud Infrastructure]            ← Commodity
↓
```

**战略判断**：
- 公司处于 Custom → Product 演化窗口，是合理的"卖铲子"位置
- 但上游（大模型）演化到 Commodity 的速度若快于下游（机器人产品）的成熟，公司的差异化窗口会被压缩
- 真正的护城河在于：能否在客户成功部署的过程中沉淀出独家数据 / 流程优势（Process Power），把自己从"工具供应商"演化为"行业基础设施"

## 与其他框架的配合

- **+ S-Curve**：S-Curve 告诉你"性能演化在哪一段"，Wardley 告诉你"市场结构演化到哪一段"
- **+ 7 Powers**：Wardley Map 上每个组件的 Power 来源不同。Custom 阶段的 Power 多来自 Process / Cornered Resource，Commodity 阶段的 Power 多来自 Scale Economies
- **+ Hype Cycle**：Wardley 是结构性视角，Hype Cycle 是心理周期视角。两者经常背离——Hype 峰期的技术可能仍在 Genesis 阶段

## 用这个框架时常见的错误

1. **图画得太精细**。Wardley Map 是讨论工具，不是工程图。20 个组件已经偏多。
2. **静态画图，不画演化**。没有箭头的 Wardley Map 是没用的。
3. **不区分"是什么"和"应该是什么"**。地图应该反映现状；战略选择是基于地图的下一步动作。
4. **忽略政策与监管的影响**。在某些行业（医疗、自动驾驶、金融），监管会让组件长期停留在某个阶段。
