# TRL：技术成熟度等级（Technology Readiness Level）

来源：NASA / DARPA / 欧盟 H2020。把一项技术的成熟度量化到 1-9 级。**硬科技与早期技术评估**的标准框架。

## 9 个等级

| TRL | 名称 | 描述 | 典型证据 |
|---|---|---|---|
| **1** | 基本原理观察 | 科学发现，仍是论文阶段 | 学术论文 |
| **2** | 技术概念形成 | 提出应用方向，无实验 | 论文 + 概念设计 |
| **3** | 概念验证 | 关键功能在实验室证明 | 实验室原型 |
| **4** | 实验室原型 | 关键组件在受控环境工作 | 实验室 demo |
| **5** | 相关环境验证 | 在模拟真实条件下验证 | 受控环境测试 |
| **6** | 原型在相关环境演示 | 接近真实环境的原型 | Field test 报告 |
| **7** | 原型在运行环境演示 | 真实场景下试运行 | 早期客户试点 |
| **8** | 系统完成与鉴定 | 通过认证，可量产 | 认证报告、量产 line |
| **9** | 系统在运行环境中实证 | 多客户、规模商业化 | 持续营收、复购 |

## Handoff 提示库（TRL 等级 → 下游合作者参考）

技术分析师只判断 TRL 等级，**不下结论**。以下表格供下游合作者按等级取用：

| TRL | → 投资合作者：阶段适配 + 主要风险 | → 媒体合作者：故事张力 |
|---|---|---|
| 1-3 | Pre-seed / Seed；技术能不能成是核心风险 | "颠覆性想法 / 实验室里的未来" |
| 4-5 | Seed / A 轮；实验室能不能放大 | "首个 demo" / 首次走出实验室 |
| 6-7 | A / B 轮；真实场景能不能跑 | "首批客户验证 / 死亡谷" |
| 8 | B / C 轮；规模化 + 单位成本 | "即将规模商业化 / 量产前夜" |
| 9 | C 轮以后 / PE；维持增长 + 防护城河 | "新一代基础设施 / 产业地图" |

## 如何判断 TRL（实操）

### 关键问题清单

1. 技术目前在什么环境下被验证过？（实验室 / 受控 / 真实）
2. 是否有第三方独立复现？
3. 是否有真实付费客户？（注意区分"试点合作"与"商业付费"）
4. 是否通过相关认证 / 标准 / 合规审查？
5. 单位经济（unit economics）是否跑通？

### 不同领域的 TRL 锚点

**AI/大模型**：
- TRL 3：论文 + 单次 demo
- TRL 5：开源 benchmark 上达到 SOTA
- TRL 7：部分企业试点 / 真实业务集成
- TRL 9：多家头部客户长期使用 + 复购

**生物医药**：
- TRL 3：体外细胞实验
- TRL 5：动物模型
- TRL 6：Phase I 临床
- TRL 7：Phase II 临床
- TRL 8：Phase III 临床 / 注册
- TRL 9：上市销售

**硬件/机器人**：
- TRL 4：可工作的实验室原型
- TRL 6：能在真实工厂/家庭环境运行的小批量
- TRL 7：合作客户试点部署
- TRL 8：通过认证 + 量产
- TRL 9：规模化交付与售后

**新能源/材料**：
- TRL 4：实验室小样
- TRL 5：吨级中试
- TRL 6：万吨级中试 / Pilot Plant
- TRL 7：示范工厂
- TRL 8：商业化首条产线
- TRL 9：多个产线 + 规模化

## 常见误判信号

| 看到的话术 | 实际可能的 TRL | 提醒 |
|---|---|---|
| "我们的技术已经突破了关键瓶颈" | TRL 3-4 | 实验室证明 ≠ 工程化 |
| "我们和 XX 大客户深度合作" | TRL 6-7 | 合作 ≠ 付费 |
| "已经在 XX 家客户部署" | 需追问规模 | 5 家小客户 vs 1 家大客户差异巨大 |
| "我们即将量产" | TRL 7-8 | "即将" 在硬科技领域常常是 12-24 个月 |
| "我们已经规模化交付" | 需看复购率 | 一次性大单 vs 重复采购 |

## 跨级跳跃的成本

经验法则：每跨一级 TRL，资金需求大致增加一个数量级（领域依赖）。

例（粗略）：
- TRL 3 → 4：百万级
- TRL 4 → 6：千万级
- TRL 6 → 8：亿级
- TRL 8 → 9：十亿级

这就是为什么硬科技公司在某些 TRL 段（如 6 → 7）"死亡谷"特别明显——融资难度跳跃式上升。

## 应用模板

```
公司/技术：__________
所在领域：__________

TRL 自评：__级
  依据：__________

TRL 主要瓶颈（下一级的关键不确定性）：
- __________
- __________

跨入下一级所需：
- 时间：__月
- 资金：__万 / 亿
- 关键里程碑：__________

信心等级：__________

Handoff Hints：
- → 投资合作者：该 TRL 阶段在该子赛道的典型估值参考 / 是否处于"死亡谷"段 / 跨级所需资金量级
- → 媒体合作者：该 TRL 阶段对应的故事张力 / 是否处在公众未注意但即将放量的窗口
```

## 用这个框架时常见的错误

1. **把 demo 等同于 TRL 5**。在受控好的环境下做 demo 只能算 TRL 3-4。
2. **不区分"看上去通了" 与"经济上能闭环"**。TRL 9 的核心是单位经济 + 复购，不只是技术能用。
3. **跨领域硬套**。不同行业的 TRL 锚点差异巨大，必须用所在行业的标准。
4. **忽略 TRL 倒退**。环境变化（监管、供应链、对手追上来）会让 TRL 实质性倒退。
