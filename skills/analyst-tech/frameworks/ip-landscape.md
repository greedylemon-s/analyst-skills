# IP Landscape & FTO（专利格局与自由实施分析）

判断一项技术的"IP 护城河强度" + "侵权风险"。硬科技领域严肃技术评估的必做项；任何涉及核心 IP 的赛道都适用。

## 两个核心问题

1. **IP Strength**：这家公司拥有的 IP 能否阻止别人做同样的事？
2. **FTO（Freedom to Operate）**：这家公司的产品能否在不侵犯他人专利的情况下持续销售？

这两个问题相互独立。一家公司可以"自己有 IP 但实际可执行性弱"，也可以"专利数量少但 FTO 干净"。

## IP Strength 评估

### 维度 1：数量（quantitative）

- 公司专利总数
- 近 3 年专利申请增速
- 与同行的对比

注意：**数量不等于强度**。一份核心专利可能比 100 份外围专利更值钱。

### 维度 2：质量（qualitative）

| 指标 | 怎么看 |
|---|---|
| **权利要求范围** | 独立 claim 是否覆盖核心方法 / 装置 |
| **引用次数** | 被后续专利引用越多越核心 |
| **同族专利** | 是否在 US/EP/CN/JP 等关键市场均有布局 |
| **法律状态** | 是否授权、是否在诉讼中、是否有 invalidity 挑战 |
| **剩余有效期** | 申请日 + 20 年，剩余年限 |

### 维度 3：可执行性（enforceability）

- 是否在"对手最难绕开"的位置布局
- 是否存在容易被设计绕开的破绽
- 公司是否有 IP 诉讼经验或意愿

### 维度 4：所有权清洁度

- 关键 IP 是否在公司名下，而非个人 / 前东家 / 关联方
- 是否存在职务发明纠纷风险（创始人在前东家时期的发明）
- 学术合作产生的 IP 归属是否清晰

## FTO 评估流程

### Step 1：定义产品/技术边界

- 公司当前产品涉及哪些技术组件？
- 每个组件涉及哪些方法、装置、用途？

### Step 2：检索相关在先专利

主要数据库：
- **Google Patents**（免费，全球，覆盖全面）— https://patents.google.com
- **USPTO PatFT/AppFT**（美国官方）
- **EPO Espacenet**（欧洲）
- **WIPO PATENTSCOPE**（PCT 国际）
- **中国国家知识产权局 / SIPO**
- **付费工具**：Innography, Derwent, PatSnap, IncoPat（国内）

### Step 3：分类排查

把检索结果按"威胁等级" 分类：
- **高威胁**：claims 直接覆盖公司核心产品的关键功能
- **中威胁**：可能覆盖但有绕开空间
- **低威胁**：相关但不直接冲突

### Step 4：设计 workaround 或 license 路径

对每一项高/中威胁专利：
- 能否通过技术替代绕开？
- 能否谈判 license？成本估算？
- 能否挑战其有效性（prior art search）？

## 关键检索技巧

### 关键词扩展

不要只搜公司名。要搜：
- 创始人姓名（找其个人专利）
- 前东家（找可能的职务发明）
- 技术关键词的多种表达（包括术语、缩写、同义词、各国语言）
- IPC / CPC 分类代码（精确定位领域）

### 国别策略

- 公司主要市场国 + 主要供应链国 + 主要客户国都要查
- 中国市场必查 SIPO 与 IncoPat（很多本土专利在英文库不全）

### 标准必要专利（SEPs）

涉及通信、视频编解码、Wi-Fi 等标准的，必查 ETSI / IEEE / ITU 公告的 SEPs。

## 软件 / AI 时代的特殊问题

### 开源 license 风险

AI / 软件公司的"IP 雷区"往往不是专利而是 license：

| License | 风险 |
|---|---|
| MIT / Apache 2.0 | 低风险 |
| GPL / AGPL | **传染性**：商业产品可能被迫开源 |
| LGPL | 链接限制 |
| BUSL（Business Source License）| 商业使用受限（如 Sentry、HashiCorp 部分产品）|
| 模型权重的特殊 license | 如 Llama、Falcon 等都有商用限制条款 |

**核查方法**：扫描公司开源依赖（package-lock.json / requirements.txt 等），用 FOSSA / Snyk / Black Duck 等工具自动化分析。

### 训练数据 IP

AI 模型的训练数据若包含版权内容，存在系统性 IP 风险。已发生案例：NYT vs OpenAI、Getty Images vs Stability AI、Reddit 与 LLM 公司的合规对抗等。

判断点：
- 训练数据来源是否完全可追溯？
- 是否签过授权？
- 各国相关判例的演化（美国 fair use、欧盟 AI Act、中国《生成式 AI 服务管理暂行办法》）

## 应用模板

```
公司：__________

IP Strength：
- 专利数：__项（已授权 / 申请中分开统计）
- 核心专利：__项（独立 claim 覆盖核心技术）
- 地域布局：US/EP/CN/JP 是否齐全
- 同族扩展：__
- 法律状态：__
- 所有权清洁度：__

FTO 风险：
- 高威胁专利：__项
- 主要威胁方：__（公司 / 个人）
- 是否需 license：__
- 是否需 redesign：__
- 是否存在职务发明风险：__

开源 / 数据 IP：
- 关键开源依赖：__
- 训练数据合规性：__
- license 雷区：__

综合判断：
- IP 是否构成有效护城河：是 / 否 / 弱
- FTO 是否构成商业化障碍：__
- 12 个月内 IP 相关风险事件概率：低 / 中 / 高

信心等级：__________

Handoff Hints：
- → 投资合作者：IP 是否构成 hard block；FTO 风险是否需在 term sheet 阶段澄清
- → 媒体合作者：是否存在未被广泛报道的 IP 诉讼 / 职务发明纠纷（潜在独家选题）
```

## 用这个框架时常见的错误

1. **只看专利数量，不看 claim**。100 个外围专利可能挡不住 1 个核心专利。
2. **忽略地域差异**。美国授权的专利在中国不能直接执行（反之亦然）。
3. **不查个人专利**。创始人在前东家期间的发明常常构成最大 FTO 风险。
4. **把"申请中" 当"已授权"**。申请中的专利无执行力，最终可能被驳回或大幅缩 claim 范围。
5. **忽视开源 license**。软件/AI 公司的 IP 风险常常在 license 而非专利。
