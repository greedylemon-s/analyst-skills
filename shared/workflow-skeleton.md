# 通用工作流骨架（7 步）

所有 analyst-* skill 共享的标准作业流程骨架。各 skill 在自己的 `workflow.md` 里可以 extend 每一步的细节（如取证清单、框架映射），但骨架不变。

每一步都要持续问自己：**"我是在追溯证据 + 第一性思考 + 纵横向分析，还是在按框架填空？"** 后者不是分析师作品。

---

## Step 0：接单与定义（5-10% 时间）

把模糊问题变成可分析的具体问题。

**通用必问 3 问**（用户没回答则主动问）：
1. **问题对象是什么？** —— 各 skill 在自己的 workflow.md 里枚举可能的对象类型
2. **时间窗口？** —— 现状评估 / 趋势研判 / 历史复盘
3. **深度需求？** —— one-pager / deep-dive / discussion

**输出**：写一句话定义"我要回答的核心问题"。

---

## Step 1：知识库回查（5% 时间）

避免重复劳动，调用历史积累。读 skill 自己的 `knowledge/README.md`，按下面顺序找：
- 同对象（公司 / 标的 / 选题）是否有归档
- 同赛道 / 同领域是否有归档
- 同类型分析是否有 playbook
- 是否有相关教训

命中 → 直接引用历史结论作为起点，重点更新自上次以来的变化。
未命中 → 标记本次任务"待归档"，结束时优先沉淀。

---

## Step 2：框架选择（10% 时间）

明确"为什么用这些框架来回答这个问题"。

- 通用框架见 [frameworks/README.md](frameworks/README.md)
- skill 专属框架见各 skill 自己的 `frameworks/README.md`
- 各 skill 在 workflow.md 里给出"问题类型 → 推荐框架组合"映射表

**必须做**：在输出中**写明选了哪些框架以及为什么**。如果某框架不适合，说明为什么不用比硬套更专业。

---

## Step 3：信源取证（30-40% 时间，最重要）

用多源独立证据支撑每一个关键事实。**找不到的证据明示"未知"，不脑补。**

### Step 3.0：开搜前 30 秒 — Live-Search 分类

列出关键事实清单，给每条标 🔴/🟡/🟢（详见 [sources/live-search-policy.md](sources/live-search-policy.md)）：
- 🔴 必须 WebFetch（近 6 个月事件 / 最新数字 / 监管动态 / 人物动态）
- 🟡 建议 WebFetch（6-18 个月）
- 🟢 可用模型记忆（>18 个月稳定事实 / 定义性概念）

🔴 类**未做 WebFetch 直接输出 = 违反铁律 2**。

### Step 3.1：三角验证

- ≥3 个独立信源 + 至少 1 个 Tier 1 + 至少 1 个 Tier 2
- 中英双语（涉及中国市场或华人圈话题）
- 关键事实清单：各 skill 在自己 workflow.md 里枚举（如 tech 的"技术性能/团队/专利"、vc 的"估值/融资/客户"、media 的"先例/受众反响/独家信源"）

### Step 3.2：追溯到一手

每个引用追到最一手层级（公告原文 / 财报章节 / 论文 figure / 监管原始公告）。
- 真追到原文 → 标 ⁽¹ˢ⁾
- 只看了媒体对它的转述 → 标 ⁽¹ʳ⁾ 并降信心
- 操作模板见 [sources/information-tracing.md](sources/information-tracing.md) 的"二手→一手追溯模板"

**初次搜索失败 → 走升级阶梯**（5 级升级 + "何时合理放弃"，同上文件 Part 2）。

### Step 3.3：取证附录（强制留痕）

每个 WebFetch 在输出的"取证附录"里记一条：

```
| 事实 | Query | Tier | 摘要 | 进主输出？ |
|---|---|---|---|---|
| 昇腾 910C 量产时间 | site:huawei.com 昇腾910C 2025 | 1 | 华为 IR 页 2025.6 量产 | ✅ |
| DeepSeek 用昇腾训练 benchmark | DeepSeek 昇腾 训练 -site:zhihu.com | — | 无可信 source | 进未知清单 |
```

让任何人能审计搜索质量。黑盒输出 = 不可信。

### Step 3.4：饱和度自检 + 持续维护未知清单

Step 3 收尾前过饱和度清单（见 [sources/information-tracing.md](sources/information-tracing.md) 的 Part 6）：
- [ ] ≥3 独立信源 / Tier 均衡 / 反例已搜 / 中英双语 / 🔴 全 fetch / 追溯深度合理

**未知清单**：每次遇到"找不到"或"信源冲突无法判断"的项，当场记录。**清单为空 = 几乎一定是没在认真找未知**。

---

## Step 4：综合分析（20% 时间）

把证据 + 框架变成判断。**五种核心能力的痕迹必须都看得见**——见 [methodology/01-five-capabilities.md](methodology/01-five-capabilities.md)。

5 道思维操作：
1. 第一性原理 sanity check — **强制触达 ≥2 类约束**（物理 / 信息 / 经济 / 制度 / 生物），单类（特别是只到经济）= 浅。详见 [frameworks/first-principles.md](frameworks/first-principles.md)
2. 纵向 why × 5（向下挖根因）
3. 纵向 so what × 5（向上推涵义）
4. 横向 2-3 个跨域类比（并写出"在哪里失效"）
5. 历史时间轴 3-7 个真正的转折点

三层表达结构：**事实 → 解释 → 判断**。

### 反向考虑 → 竞争性假设（升级版）

每个核心判断后，**强制显性枚举竞争性假设**：
> "同样的事实，是否有 ≥2 种合理解释？我选了我的版本而不是 X，是因为证据更强，还是因为我先想到的？"

格式：
```
主判断：X（概率 ≈ 55%）
替代 A：Y（概率 ≈ 30%）— 关键变量：…
替代 B：Z（概率 ≈ 15%）— 关键变量：…
我选主判断的原因：…
但 A、B 非零 → 结论应给概率分布，不应给"绝对" 断言
```

**边界**：如果替代假设全在 5% 以下，写主判断就好——刻意维持"多假设"反而是噪音。详见 [frameworks/lateral-vertical.md](frameworks/lateral-vertical.md) 的"竞争性假设"段。

量化数字必须带：**来源 / 时间 / 口径 + 量纲 4 问**（单位 / 量级 / 分母 / 时间一致）。详见 [methodology/00-ironclad-rules.md](methodology/00-ironclad-rules.md) "量化数字的处理"段。

---

## Step 5：输出（15-20% 时间）

用标准模板，让输出可比、可归档、可重读。**Handoff Hints 是每份输出的必备结尾**（见 [methodology/03-handoff-hints.md](methodology/03-handoff-hints.md)）。

模板（通用骨架）：
- `templates/one-pager.md` — 单页速评
- `templates/deep-dive.md` — 深度报告
- `templates/discussion.md` — 讨论型文档

### 通用输出前自检清单

- [ ] 每个关键事实都有**复合 Tier 标注**（⁽¹ˢ⁾/⁽¹ʳ⁾/⁽²⁾/⁽³⁾/⁽ᴹ⁾），且 ⁽¹ˢ⁾+⁽²⁾ 占比 ≥ 50%
- [ ] 每个结论都有信心等级（高/中/低）
- [ ] **第一性 sanity check 触达 ≥ 2 类约束**（物理 / 信息 / 经济 / 制度 / 生物）
- [ ] **关键数字过量纲 4 问**（单位 / 量级 / 分母 / 时间）
- [ ] why × 3+ 纵向追根
- [ ] so what × 2+ 涵义推导
- [ ] 1-2 个横向类比（且标注"在哪里失效"）
- [ ] **历史时间轴：3-7 个真正的转折点**（不是流水账）
- [ ] **竞争性假设**：每个核心判断列出 ≥2 个替代解释 + 概率
- [ ] **反例对照**：调过 [frameworks/first-principles-counterexamples.md](frameworks/first-principles-counterexamples.md) 至少 1 个同型反例
- [ ] 明确写出本次用了哪些框架、为什么
- [ ] **取证附录**：每个 WebFetch 留痕（Query / Tier / 摘要）
- [ ] **饱和度自检**：6 项过完，未达项有具体补救动作
- [ ] **未知清单不为空**
- [ ] **两个 Handoff Hints 块都已写**，且"指方向"而非"下结论"
- [ ] **Plain-Speak 双层表达**：每个核心概念首次出现都有"用大白话说"；无 jargon 堆叠
- [ ] **Feynman 自检**：给外行朋友看，30 秒内能说出"这在讨论什么" 吗

---

## Step 6：归档（5% 时间）

主动问用户：「本次有哪些洞察值得归档到 knowledge/？我建议归档以下几条：[2-4 条候选]。你看哪些保留？要不要补充什么？」

归档对象（按优先级）：
1. 可复用的判断框架 → `playbooks/`
2. 对象画像（公司 / 标的 / 选题）→ skill 自己定义子目录
3. 赛道 / 领域认知 → `sectors/` 或类似目录
4. 踩坑 / 反思 → `lessons.md`
5. 新的"未知" → `lessons.md` 或 `sectors/`

---

## 时间分配参考（deep-dive 任务）

| 步骤 | 时间占比 |
|---|---|
| 0. 定义 | 5-10% |
| 1. 知识库回查 | 5% |
| 2. 框架选择 | 10% |
| 3. 信源取证（含搜索升级 + 未知记录） | 30-40% |
| 4. 综合分析（5 道思维操作） | 20% |
| 5. 输出 | 15-20% |
| 6. 归档 | 5% |

**警戒线**：如果发现自己花了 60% 时间在"输出"上而只有 10% 在"取证"，**停下来**——这是一份印象式作品，不是分析师作品。
