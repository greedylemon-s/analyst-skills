# Live-Search Policy — 什么必须 WebFetch，什么可以靠模型记忆

**这条政策是铁律 2（三角验证）的前置条件**。在做三角验证前，必须先判断每个关键事实属于哪一档。

## 3 档分类

| 档位 | 触发条件 | 操作 | 不遵守的后果 |
|---|---|---|---|
| 🔴 **必须 WebFetch** | • 近 **6 个月**内事件<br>• 最新性能数字 / 估值 / 市占 / 价格<br>• 监管动态 / 政策变动<br>• 人物职位变动 / 团队动态<br>• 任何具体到月/季的"最新"声称 | **不 fetch 直接写 = 违反铁律 2**。即便模型"觉得知道"，也必须以 fetch 结果为准 | 输出基于过期或幻觉数据 → 用户做了错误判断 |
| 🟡 **建议 WebFetch** | • 6-18 个月内事件<br>• 中等时效的数字<br>• 不确定是否过期的事实 | 优先 fetch；若搜索失败或时间预算紧，标 ⁽ᴹ⁾（模型记忆）+ 降一级信心 | 风险中等 — 模型 1-12 月内的知识较稳，但不能保证 |
| 🟢 **可用模型记忆** | • 定义性概念（"什么是 Transformer"）<br>• 历史脉络（>18 个月的稳定事实）<br>• 已被反复印证的常识 | 直接用模型记忆，但仍标 ⁽ᴹ⁾ 让读者知道未独立核实 | 风险低 — 但**仍要标 ⁽ᴹ⁾**，不要伪装成"我看了原始资料" |

## 操作 SOP

### Step 3 取证开始前的 30 秒分类

打开关键事实清单，给每条标 🔴/🟡/🟢：

```
关键事实清单：
🔴 摩尔线程最新一轮估值              → 必 fetch
🔴 昇腾 910C 2025 量产进度           → 必 fetch
🟡 海光 DCU 历代发布时间              → 优先 fetch
🟢 CUDA 2006 年发布                  → 模型记忆 OK
🟢 NPU 与 GPGPU 架构差异              → 模型记忆 OK
```

### 不 fetch 的合理理由（必须显性写出）

如果 🔴 类未 fetch，**必须在输出里写出原因**，且降信心：

- "Web 搜索失败 + 已升级到 Level 4 未果（见取证附录）" → 进未知清单
- "用户明确要求快速速评，跳过 fetch" → 标 ⁽ᴹ⁾ + 信心降一级
- 无以上原因 = **违反铁律 2**，不允许

## 模型记忆的时效边界

作为 model，你的训练数据 cutoff 是有限的。对**接近或超过 cutoff** 的事件：
- 即便你"觉得记得"，也必须 fetch
- 模型记忆中的"近期"事件常常是幻觉合成（混合不同时期细节）

**判别**：如果你对某事的回忆带有"大约"、"应该是"、"我记得是 2024 还是 2025"等模糊措辞 → 这是幻觉信号 → 强制 fetch。
