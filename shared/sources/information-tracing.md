# 信息追溯与搜索升级阶梯

不仅要"会搜"，还要"会追"（找一手源头）+ "会升级"（搜索失败时不放弃也不脑补）+ "会停"（什么时候合理放弃并诚实声明未知）。

---

## Part 1：信息追溯（找一手源头）

**铁律**：永远追到一手信源。中间渠道（媒体转述、二手综述、社区讨论）只能作为线索，不能作为结论依据。

### 常见信息传播链与回溯路径

```
你看到的：         追到的源头：
"据报道"      →   是哪家媒体？是原创还是转载？
"业内人士"    →   具名？匿名？匿名的话谁能确认？
"数据显示"    →   哪份报告？谁出的？口径是什么？时间？
"某高管表示"  →   什么场合？原视频/原稿在哪？
"招股书显示"  →   招股书原文哪一章哪一页？哪个版本？
"论文证明"    →   论文标题、作者、发表时间、是否同行评审、可否复现？
```

### 追溯工具箱

#### ① 引用链追溯

- **Google Scholar / Semantic Scholar**：查"谁引用了 X"和"X 引用了谁"
- **Connected Papers** (connectedpapers.com)：可视化引用网络
- **Inciteful** (inciteful.xyz)：找相关论文集群

#### ② 公司原始公告

- **SEC EDGAR** (sec.gov/edgar)：美国上市公司全部文件
- **巨潮资讯网** (cninfo.com.cn)：A 股公告
- **港交所 HKEXnews** (hkexnews.hk)：港股公告
- **公司 IR 页面**：年报、季报、业绩说明会 PPT、电话会 transcript

#### ③ 政府/监管原文

- 各国政府官网（不要看媒体改写，要看通知原文）
- 监管机构问答稿（FAQ）和实施细则比新闻通稿信息量大 10×

#### ④ 个人言论的原始版本

- 视频原片（YouTube / Bilibili / 公司 webinar 回放）
- Twitter/X 原始 thread（注意是否删除、修改）
- 播客原始音频（不要只看转写）
- LinkedIn 帖子

### 追溯失败的常见情形

- **二次转述链断裂**：A 引 B，B 引 C，C 引"业内"——追到 C 就死。要么 C 是原创信源，要么这条信息不可靠。
- **数据来源被刻意模糊**：「权威报告显示」"X 行业研究院数据"——这种通常不可追。直接归入"低信心"。
- **删除/锁定**：原 Tweet 被删、原文章被撤。用 Wayback Machine 找。

### 二手 → 一手 追溯模板（4 步操作）

当你只能找到二手报道，按 4 步追到一手：

```
1. 二手文章 → 找"据 XX 报道 / 根据 XX 文件" 字样 → 锁定 source
2. source 是机构（公司 / 监管 / 期刊）→ 直接查机构官网 + 关键词
3. source 是个人（CEO 访谈 / 演讲）→ 找原始视频 / 演讲 transcript / 原始 tweet
4. 全是相互转述、找不到原始 → 把"找不到一手" 本身写入未知清单
```

**关键纪律**：三步都过不去 → **不要"暂且引用二手"**，标 ⁽¹ʳ⁾（reported）+ 降信心。混淆 ⁽¹ˢ⁾ vs ⁽¹ʳ⁾ 是出错的常见根源。

**例**：
> 看到 36 氪："据华为 2024 年财报，AI 收入超过 X 亿"
> ↓ 追溯
> 找华为 2024 年报：投资者关系页 → 年报 PDF → 索引"AI"→ 第 X 章第 X 节
> → 引用直接写："华为 2024 年报第 X 章，AI 业务（含昇腾 + 云）营收 Y 亿元⁽¹ˢ⁾"

### 信源指纹识别 — 5 秒判断网页类型

看到一个网页 URL，5 秒判断类型，**用对应信任度对待**：

| 指纹特征 | 类型 | 信任度 |
|---|---|---|
| `.gov / .gov.cn / .europa.eu` + 公告页 | 监管原文 | 最高 |
| `huawei.com/investor / sec.gov/edgar / hkexnews.hk / cninfo.com.cn` | 公司 IR / 公告 | 高 |
| `arxiv.org / nature.com / ieee.org / acm.org` + 论文 | 学术原文 | 高（注意预印 vs 同行评议）|
| 媒体网站（FT / WSJ / 财新 / 36kr）+ **有具名记者 + 引用 source** | 专业转述 | 中 |
| 个人博客 / Substack / 知乎专栏 + **有引用链 + 作者可验证** | 二手分析 | 中-低 |
| 内容农场 / SEO 网站 / 无署名 / 多平台搬运 | 噪音 | **禁止引用** |
| AI 生成内容（通用化语言 + 无具体细节 + 无明确署名） | 噪音 | **禁止引用** |

**特别警告**：2024 起 AI 生成内容大量污染中文搜索结果。判别特征：
- 写作风格平均化、缺乏个性
- 列举多但具体数字 / 案例少
- 无可验证的作者背景
- 标题 + 段落首句信息量大，越往后越空

看到这些特征 → **默认假设是 AI 生成 → 不引用**。

## Part 2：搜索升级阶梯（5 级）

初次搜索失败 → **不要放弃，也不要脑补**。按阶梯升级：

### Level 1：常规关键词搜索（baseline）

- 搜索引擎：Google + Bing + DuckDuckGo（结果差异有时巨大）
- 中文搜索：百度（仍是中文世界最全）+ 搜狗微信搜索 + 即刻搜索
- 关键词组合：实体名 + 修饰词（年份、地点、产品代号）
- 中英双语关键词都试

**失败信号**：前 2 页结果都是低质量 SEO 内容或转述同一条消息。

### Level 2：信息追溯（找原始信源、引用链、关联人物）

- 找到任何提到该话题的信息源，**反向追到原始**
- 在论文/新闻里找具名人物 → 查这个人的个人 LinkedIn / Twitter / 公开账号
- 在公司提及里找前同事 → 在 LinkedIn 上看离职员工分布
- 找"披露过此类信息的具体记者 / 分析师" → 看他们最近的同主题报道

**何时升级**：上面方法 30 分钟内无突破。

### Level 3：横向 / 侧向搜索（同义词、跨语言、跨平台、负面词）

- **同义词**：换 5-10 种说法（"AI 应用层" / "AI 中间件" / "LLM 应用栈" / "Agent platform"）
- **跨语言**：英 → 中 → 日 → 韩等。中国公司动态在中文搜中文，海外动态在英文搜英文，但反过来也要试（如海外团队评论中国公司）
- **跨平台**：搜索引擎 → 学术库 → 专利库 → GitHub → Reddit → Twitter → 知乎 → 即刻 → 微信公众号文章库（搜狗）
- **负面词**：「失败」「问题」「裁员」「下架」「诉讼」——负面信息往往揭示真相，但传播窄，需主动搜
- **特定语法**：
  - `site:` 限制网站（`site:sec.gov "Anthropic"`）
  - `filetype:pdf` 找研报
  - 时间过滤（限定近 30 天 / 12 个月）
  - 精确匹配引号 `"..."`

### Level 4：归档搜索（找被删/被锁/历史版本）

- **Wayback Machine** (web.archive.org)：网页历史版本
- **Archive.today** (archive.ph)：手动归档版本，常补 Wayback 漏的
- **Google Cache**：搜索结果旁边的 cache 链接（虽 Google 在淡化此功能）
- **邮件列表归档**：mailman.openssl.org、cncf-toc、ml.kernel.org 等技术邮件列表
- **GitHub 历史**：commit、closed issue、deleted branch
- **Wayback Machine 的 Twitter 归档**：找已删 Tweet
- **学术论文撤稿数据库**：Retraction Watch（看是否被撤）

### Level 5：第一性原理推断 + 信源缺失声明

如果 Level 1-4 都失败：

- 用第一性原理推断**可能的范围**（不是具体数字），明确写出推理链
- 输出形如：「公开信源未覆盖。基于以下推理：A、B、C，推测 X 大致在 [区间]。信心：低。」
- **绝不**写"业内估计""通常认为" 之类无追溯依据的措辞

### 仍无法支撑判断 → 进入"未知清单"

参见 Part 3 "何时合理放弃"。

## Part 3：何时合理放弃（"承认未知" 不是失败，是专业）

### 时间预算

- 单个事实点的搜索预算：**初次 5 分钟 + 升级搜索最多 30 分钟**
- 超时未果 → 进入未知清单
- 整份分析的取证总预算：根据深度需求设定（one-pager 30-60 分钟，deep-dive 4-8 小时）

### 何时合理停止

满足以下任一即可停止：
- 已走完 Level 1-4，且 Level 5 推断的不确定区间过宽（无法支撑判断）
- 该信息明确处于**信息黑箱**：未上市公司、私下融资、个人私密、未公开发表
- 该信息需要**内部渠道**（在职员工访谈、客户私下数据）才能获得，本次任务范围之外

### 何时不应该停止

以下情况虽然"搜不到" 但通常是搜索能力问题，应当继续：
- 只用了中文 / 只用了英文搜索
- 只搜了主流搜索引擎，没搜专业数据库
- 没尝试找原始信源（只看了二手转述）
- 没尝试找当事人公开账号
- 没用 Wayback Machine
- 没用第一性原理推断"大致范围"

### "未知清单" 的标准格式

每一项未知都按下列格式写入输出：

```
未知项 | 重要性 | 已尝试 | 仍未解的原因 | 解开它需要什么
------|------|------|------------|--------------
[具体事实问题] | 高/中/低 | [简述搜索路径] | [信源缺失/冲突/锁定] | [访谈XX / 等XX披露 / XX数据库订阅]
```

**例**：
| 未知项 | 重要性 | 已尝试 | 仍未解的原因 | 解开它需要什么 |
|---|---|---|---|---|
| Figure 02 当前生产成本 | 高 | 公司未公开 / 媒体只有"目标 BOM" 估算 / 供应链分析师未发布 | 公司刻意不披露，处于融资期 | 找 Tier 1 供应商访谈或等 Series C 公开 |
| Mamba 在长代码理解 benchmark 上的表现 | 中 | 原论文未覆盖 / Papers with Code 暂无 | 该 benchmark 是新提出的 | 等独立复现或自建评估 |

### "诚实未知" 的语言模板

不要写：
- 「一般认为……」
- 「业内估计……」
- 「据可靠消息……」
- 「应该会……」「可能在……」（没有依据时）

要写：
- 「公开信源未覆盖。在 [Level 1-5] 升级搜索后仍未得到可信信息。」
- 「我目前无法判断 X。如果要回答这个问题，需要 [具体的信息渠道]。」
- 「[A 信源] 与 [B 信源] 互相矛盾，且无第三方独立验证。本判断暂时挂起。」
- 「基于 [可验证事实 X、Y]，我可以推断范围是 [a, b]（信心：低），但具体值需 [验证路径]。」

## Part 4：信源批判（搜到 ≠ 可信）

每个搜到的信息都过 4 道滤网：

### 滤网 1：动机
- 这个信源**为什么** 发布这条信息？PR？学术声誉？商业利益？带节奏？
- 利益相反方说了什么？

### 滤网 2：能力
- 这个信源**有没有能力** 知道这件事？（行业身份、地理位置、时间）
- 距离事件越远 / 越间接 → 可信度递减

### 滤网 3：时间
- 信息发布时间 vs 事件发生时间
- 是否过时？是否在事件高峰期发布（需冷静后再判断）

### 滤网 4：独立性
- 这条信息是不是与你已有的"3 个信源" 中某个同源？
- 同源验证不算验证

## Part 6：取证饱和度自检（Step 3 收尾必做）

**什么时候算"找够了"？** 不是凭感觉，是过清单：

- [ ] 关键事实已有 **≥3 个独立信源**（铁律 2）
- [ ] 至少 **1 个 Tier 1 + 1 个 Tier 2**（信源结构均衡）
- [ ] 已主动搜过**反例 / 否定证据**（不只搜支持结论的）
- [ ] 已搜过**中英文双语**（涉及中国 / 华人圈话题）
- [ ] 🔴 类事实**全部 fetch 完成**（见 [live-search-policy.md](live-search-policy.md)）
- [ ] **追溯深度合理**：⁽¹ˢ⁾ + ⁽²⁾ 占比 ≥ 50%；⁽ᴹ⁾ + ⁽¹ʳ⁾ + ⁽³⁾ 不应过半

任一未达 → 升级搜索 or 进未知清单 or 降信心。**不要因为"我已经找了很多了"就停**——饱和有清单，不是感觉。

**自检输出**（写在取证附录最后）：
```
饱和度自检：✅ 三角 ✅ Tier 均衡 ❌ 反例未搜 ✅ 中英双语 ✅ 🔴 全 fetch
未达项 → 升级 / 进未知 / 降信心：[具体动作]
```

## 自检：每次取证结束问自己

- 我追到的最近一手源头是什么？
- 如果有人质疑我的每个关键事实，我能不能立刻提供 ≥3 个独立信源的链接？
- 我有没有把"找不到" 当"不存在"？（这是最常见的错误）
- 我的未知清单非空吗？如果空，是真的全找到了，还是没在认真找？
- 我有没有为了让分析"看起来完整" 而在缺信源处填空？
- **饱和度清单是否每条都过？** ⁽¹ˢ⁾ 和 ⁽¹ʳ⁾ 我是不是混淆了？
- 我有没有把 ⁽ᴹ⁾（模型记忆）伪装成"我看了原始资料"？

如果以上任一答"有"，**重写**那一段，改成诚实的标注与未知。
