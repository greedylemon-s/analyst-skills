# 信源目录与可信度分级

技术分析师的"取证地图"。**关键事实必须 ≥3 个独立信源三角验证**——这是 SKILL.md 的铁律。

## 信源三级分类

```
Tier 1 — 一手数据（最高可信度）
├── 公司官方
│   ├── 招股书 / 年报 / 季报
│   ├── 监管文件（SEC EDGAR / 巨潮 / HKEX）
│   ├── 技术白皮书 / 官方博客
│   └── 开源代码仓库（GitHub）
├── 学术与专利
│   ├── 同行评审论文（顶会、期刊）
│   ├── arXiv preprint
│   └── 专利原文（USPTO/EPO/WIPO/SIPO）
└── 政府/统计
    ├── 各国统计局
    ├── 央行 / 监管机构发布
    └── 国际组织（IMF、世行、OECD）

Tier 2 — 专业分析（中高可信度）
├── 顶级行业分析师
│   ├── Gartner / Forrester / IDC / CB Insights
│   ├── 信通院 / 艾瑞 / 易观 / QuestMobile
│   └── 投行研报（Goldman、Morgan Stanley、中金、CICC）
├── 独立分析媒体
│   ├── Stratechery / Benedict Evans / The Information
│   ├── 晚点 LatePost / 36氪深度 / 极客公园
│   └── 行业垂直媒体（机器之心 / 量子位 / The Verge / Tech Crunch）
└── 顶级 VC 公开分析
    ├── a16z / Sequoia / Bessemer / Coatue
    └── 源码 / 红杉中国 / 高瓴

Tier 3 — 社区与综合（参考可信度，需交叉验证）
├── 综合财经媒体（WSJ、FT、Bloomberg、彭博 / 财新 / 第一财经）
├── 技术社区（Hacker News / Reddit / Lobsters / 知乎 / 即刻）
├── 社交媒体（Twitter/X 技术圈、Substack）
└── 招聘信息（LinkedIn / 拉勾 / Boss 直聘）— 反推团队、技术栈
```

## 三角验证规则

**任何关键事实，至少满足以下之一**：

| 验证强度 | 信源组合 |
|---|---|
| 强（推荐） | 1 Tier 1 + 1 Tier 2 + 1 Tier 3 |
| 中（可接受） | 2 Tier 1 |
| 中（可接受） | 1 Tier 1 + 2 Tier 2 |
| 弱（需标"未充分验证"） | 2 Tier 2 / 3 Tier 3 |
| 不可用 | 仅 1 Tier 3 |

**独立性要求**：3 个信源不能源于同一原始报道。如果"36 氪报道 + 虎嗅转载 + 知乎讨论"都在引用同一个原始爆料，那只算 1 个信源。

## 信源使用的纪律

### 引用必须可追溯 — 追到"最一手层级"

不要写"据业内人士透露 / 据报道 / 据相关消息"。每个引用都必须有：
- 原始信源（不是转载）
- 发布时间（精确到月，必要时精确到日）
- 直接链接（如非付费内容）

#### 什么算"最一手"

| 事实类型 | 最一手 = | 不是最一手（仍可用作线索） |
|---|---|---|
| 公司动态 | 公司官网公告 / IR 页 / 招股书章节 | 科技媒体转述 |
| 财务数据 | 招股书 / 财报章节号 | Bloomberg/Reuters 摘要 |
| 技术指标 | 论文 figure / 官方 spec sheet | PR 通稿 / Benchmark 营销页 |
| 监管事件 | 监管机构原始公告（BIS Federal Register / SEC EDGAR / 国务院公报） | 新闻媒体改写 |
| 个人言论 | 视频原片 / 演讲 transcript / 原始 tweet | 媒体引用 / 二次解读 |
| 学术结论 | 原论文（注意预印 vs 同行评议） | 综述论文 / 媒体科普 |

**为什么不停在二手**：二手会做选择性摘编、有翻译误差、把"达到 X 性能"误传成"超过 X 性能"。一手是事实的最低延迟点。

**追溯成本权衡**：如果一手在付费墙后 / 已下架 / 需要专业数据库，权衡时间预算。能找到一手 → 用一手并标 ⁽¹ˢ⁾；只能用二手 → 标 ⁽¹ʳ⁾ 并降信心。具体操作见 [information-tracing.md](information-tracing.md) 的"二手→一手追溯模板"。

### 中英文双轨

涉及中国市场或华人技术圈的话题，**只用英文信源是危险的**。例：
- 中国 AI 政策的英文报道往往滞后 + 失真
- 中国 startup 的真实进展常常先在脉脉 / 雪球 / 即刻爆出
- 国产硬件的真实测试常常先出现在知乎 / B 站技术 UP 主

### 时间敏感性

技术分析有强时间衰减。一般规则：

| 类型 | 可接受的"过期"程度 |
|---|---|
| 市场规模数据 | ≤12 个月 |
| 技术性能 benchmark | ≤6 个月 |
| 融资 / 估值 | ≤3 个月 |
| 产品进展 / 团队变动 | ≤1 个月（在快速变化领域更短） |
| 政策 / 监管 | 实时跟进 |

### 防止信源同源化

同源化是分析失败的常见原因。常见症状：
- 多家媒体引用同一份 IDC 报告 → 仍是 1 个信源
- 多家分析师引用同一个公司 PR → 仍是 1 个信源
- 多个论文出自同一个实验室 → 不够独立

**对治**：刻意寻找"利益相反"的信源。看好该公司的 + 看空该公司的 + 中立第三方。

### 信源批判性

每次引用前问：
- 这个信源的**动机**是什么？（PR / 学术声誉 / 商业利益）
- 这个信源的**视角盲点**是什么？（卖方分析师天然倾向看多）
- 是否有**未披露的利益关联**？（VC 评论自己投的项目）
