# shared/templates — 输出模板

三种通用输出格式。所有 `analyst-*` skill 共用，各自的 SKILL.md 指向这里。

| 模板 | 场景 | 规模 |
|---|---|---|
| [one-pager.md](one-pager.md) | 单点问题 / 快速判断 | 800-1500 字 |
| [deep-dive.md](deep-dive.md) | 综合评估 / 全景覆盖 | 3000-8000 字 |
| [discussion.md](discussion.md) | 概念厘清 / 一起走分析路径 | 2000-5000 字 |

## 共同硬性要求（所有模板）

无论用哪种模板，以下段落是**项目级硬约束**：

- ✅ **复合 Tier 标注** ⁽¹ˢ⁾⁽¹ʳ⁾⁽²⁾⁽³⁾⁽ᴹ⁾（每个关键事实）
- ✅ **第一性 sanity check ≥ 2 类约束**
- ✅ **量纲 4 问**（任何关键数字）
- ✅ **反例对照**（调 counterexamples 库 ≥1 个）
- ✅ **竞争性假设**（每个核心判断列 ≥2 个替代）
- ✅ **未知清单不为空**
- ✅ **取证附录**（WebFetch 日志 + 饱和度自检）
- ✅ **Handoff Hints**（两块都写，指方向不下结论）
- ✅ **Plain-Speak 双层**（每个核心概念首次出现）

省略任一 = 不合格输出。

## 选模板规则

不确定用哪种？**直接问用户**：
> "这次需要快速速评（≈一页）、深度技术报告（5-10 页）、还是讨论型文档（聚焦概念厘清与方法论）？"

## 修改约定

改这些模板前确认：
- 是真正通用（所有 analyst-* 适用）？
- 还是只某 skill 需要？
- 通用 → 改这里 + 留 ADR 到 项目 decisions（内部，未公开）
- 仅某 skill → 在该 skill 自己目录里 override
